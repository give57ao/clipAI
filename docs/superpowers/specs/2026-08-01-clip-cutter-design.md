# 수동 구간 자르기 exe 설계 (2026-08-01)

## 배경

`clipAI_launcher.exe`(HUD 올킬 자동탐지)와는 별개로, 사용자가 직접 골라둔
"이 영상의 몇분부터 몇분까지" 구간들을 텍스트로 적어두면 그대로 잘라주는
두 번째 실행기가 필요하다. HUD 판독이나 파이썬 파이프라인을 전혀 거치지
않고, ffmpeg 스트림 복사만으로 빠르게 클립을 뽑는 독립 도구다.

- **배포 대상**: 본인 PC 전용 (`clipAI_launcher.exe`와 동일 전제 — ffmpeg가
  PATH에 있음을 그대로 사용).
- **입력 방식**: 파일 경로 + 자를 구간들을 한 줄씩 적은 `.txt` 파일을
  만들어서 exe에 드래그 앤 드롭.
- **UI**: `clipAI_launcher.exe`와 동일한 검은 콘솔 창 UX.

## 입력 형식

한 줄에 하나씩:

```
<영상 절대경로>.mp4        <구간1>, <구간2>, ...
<영상 절대경로>.mp4        없음
```

- **경로/구간 경계 판단**: 한 줄에서 `.mp4`가 처음 나오는 위치까지를 경로로
  본다(파일명 자체에 공백이 섞여 있어도 `.mp4` 확장자로 경계를 확정할 수
  있음). `.mp4` 뒤 나머지 문자열이 구간 목록이다.
- **구간 표기**: `시작 - 종료` 형태, 콤마로 여러 구간 나열. 끝에 콤마가
  하나 남아도(빈 토큰) 무시.
- **시간 표기**: 콜론 개수로 자동 판별.
  - `M:SS` / `MM:SS` → 분:초 (예: `13:45` = 13분45초)
  - `H:M:SS` → 시:분:초 (예: `1:8:55` = 1시간8분55초)
  - 각 파트는 정수로 파싱(자릿수 패딩 여부 무관: `1:8:55`도 `01:08:55`도
    동일하게 처리).
- **스킵 표기**: 구간 자리에 `없음`(공백 포함 트림 후 정확히 일치) 또는
  완전히 빈 문자열이면 그 줄의 영상은 통째로 건너뛴다.
- **여러 `.txt` 동시 드래그**: 각 `.txt`를 독립적으로 순서대로 처리.
- **`.txt`가 아닌 파일을 드래그**: "무시: <파일명> (txt 아님)" 로그만
  남기고 처리하지 않음(파이프라인 미실행).

## 자르기 방식

- `ffmpeg`를 subprocess로 직접 호출(PATH에서 찾음), 스트림 복사
  (`-c copy`, 재인코딩 없음 — 빠르지만 키프레임 스냅 발생).
- **시작 시각 안전막**: 요청한 시작 시각보다 **2초 앞당겨서** `-ss`(입력
  시크, `-i` 앞에 배치)로 넘긴다. 이렇게 앞당긴 값이 0초 미만이 되면
  0으로 클램프.
- **길이**: `-t`로 "종료 시각 − 원래 요청 시작 시각 + 2초"를 지정(끝은
  요청하신 그대로, 안전막으로 당긴 2초만큼 앞부분에 여유가 더 붙음).
- `-avoid_negative_ts make_zero`를 붙여 입력 시크 후 타임스탬프 깨짐을
  방지.
- ffmpeg가 PATH에 없으면 프로그램 시작 시점에 바로 에러 메시지를 출력하고
  종료(파이프라인 미실행).

## 출력

- 저장 위치: `E:\clipai_result\manual_clips\`
- 파일명: `<원본파일명(확장자 제외)>_<시작시각>.mp4`
  - 시작시각 표기: 분초만 있으면 `13m45s`, 시가 있으면 `1h08m55s`
    (분·초는 2자리 패딩, 시는 패딩 없음).
  - 예: `2026-06-30 22-24-03_13m45s.mp4`

## 에러 처리 (해당 항목만 건너뛰고 계속 진행)

| 상황 | 처리 |
|------|------|
| 영상 파일이 실제로 존재하지 않음 | "건너뜀: <파일명> (파일 없음)" 출력, 그 줄 전체 스킵 |
| 구간 시간 형식 파싱 실패 | "건너뜀: <파일명> 구간 '<원문>' (형식 오류)" 출력, 그 구간만 스킵 |
| 종료 시각이 시작 시각보다 빠르거나 같음 | "건너뜀: <파일명> 구간 '<원문>' (시작≥종료)" 출력, 그 구간만 스킵 |
| ffmpeg 실행이 0이 아닌 종료 코드로 실패 | ffmpeg의 stderr를 그대로 콘솔에 보여주고 그 구간만 스킵, 나머지 계속 진행 |
| ffmpeg가 PATH에 없음 | 명확한 에러 메시지 출력 후 키 입력 대기, 프로그램 즉시 종료 |
| `.txt`가 아닌 파일을 드래그 | "무시: <파일명> (txt 아님)" 출력, 넘어감 |
| 유효한 구간이 하나도 없음(전부 스킵/없음) | "처리할 구간이 없습니다" 출력 후 키 입력 대기, ffmpeg 미실행 |

## 콘솔 UX

`clipAI_launcher.exe`와 동일한 패턴:

1. 구간별 진행 로그: `[clip] OK <원본파일명> <구간> -> <출력파일명>` /
   `[clip] SKIP <사유>`
2. 완료 후 요약: `성공 N개 / 건너뜀 M개`
3. 결과 폴더 경로(`E:\clipai_result\manual_clips`)를 보여주고 열지 여부
   (Y/N) 질문 → Y면 `os.startfile()`로 탐색기 오픈(폴더 없을 시 예외
   가드 포함 — 첫 번째 exe에서 겪은 것과 동일한 함정).
4. "아무 키나 누르면 닫힙니다" 대기 후 종료.

## 구성 요소

- 신규 `files/clip_cutter.py` — 표준 라이브러리 + `subprocess`로 시스템
  `ffmpeg.exe`를 직접 호출. 파이썬 파이프라인(`batch_hud_ace_pipeline.py`)
  이나 torch/opencv/easyocr을 전혀 거치지 않으므로 `clipAI_launcher.exe`
  보다도 더 가볍다.
- PyInstaller onefile 빌드 → `clipAI_clipper.exe`.

## 테스트 계획

- 시간 문자열 파싱 함수: `"13:45"`, `"1:8:55"`, `"01:08:55"`, 잘못된
  형식(`"abc"`, `"1:2:3:4"`) 각각 검증.
- 한 줄 파싱 함수: 경로/구간 분리(`.mp4` 경계 판정), `없음`/빈 문자열
  처리, 트레일링 콤마, 여러 구간 파싱.
- 출력 파일명 생성 함수: 분초만 있는 경우 / 시가 있는 경우 각각.
- ffmpeg 커맨드 조립 로직: 2초 안전막 적용, 0초 미만 클램프,
  `-avoid_negative_ts make_zero` 포함 여부 — 실제 ffmpeg 실행 없이
  monkeypatch로 커맨드 배열만 검증.
- `main()` 오케스트레이션: 여러 줄 중 일부만 성공/스킵되는 시나리오,
  `.txt` 아닌 파일 드래그, 유효 구간 0개 시나리오 — subprocess와
  `os.startfile`을 monkeypatch로 검증.

## 범위 밖 (이번에 하지 않는 것)

- HUD 판독이나 `batch_hud_ace_pipeline.py`와의 연동 — 이 도구는 사용자가
  이미 골라둔 구간을 그대로 잘라내는 용도로, 자동 탐지와 무관.
- 재인코딩 정밀 자르기 — 스트림 복사 방식으로 확정(사용자 선택).
- GUI — 콘솔 창으로 충분.
- 겹치는 구간 검증, 구간 개수 제한 등 추가 유효성 검사 — 불필요.
